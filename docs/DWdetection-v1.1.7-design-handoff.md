# DW Detection v1.1.7 设计交付说明

> 更新日期：2026-08-21
> 用途：供产品、设计、前端与后端研发对照实现。本文记录 v1.1.7 最新原型的页面结构、交互逻辑、状态规则与研发边界；可运行效果以 `deliverables/DWdetection-v1.1.7-preview.html` 为准。

## 1. 版本目标与范围

目标用户是缺少算法经验的外部三方交付人员。产品通过清晰的状态反馈和行动建议，帮助用户完成“导入数据 → 标注与质量评估 → 发起训练 → 发布与验证”的闭环，降低漏标、错标和训练返工风险。

v1.1.7 已覆盖：

- 数据集导入、列表管理、标注入口与异常图片自动清理。
- 六维样本质量评估、标注质量双指标、问题排序与直接整改行动。
- 数据集详情、图片去重、标注教程与首次使用引导。
- 模型与版本分层管理、训前检查、训练状态演示、发布及表计类验证。
- 表计模板配置与指针模板四步静态指引。
- 单文件 HTML 离线预览和 Vue 3 源码交付。

本版本不包含真实算法服务、真实训练调度、站间数据共享、复杂几何标注及非表计类模型验证。

## 3. DW 运营视觉规范

### 3.1 使用原则

- 页面主体保持安静、紧凑，适合反复操作和快速扫描。
- 页面底色须与顶部导航栏明确区分；内容底色更深，模型行与版本表头也需保持层级差异。
- 毛玻璃用于弹窗、浮层、工具栏等有明确层级的区域；普通页面区块和表格不统一套磨砂外壳。
- 颜色优先使用 `src/design-tokens.ts` 或 Element Plus 语义变量，不在组件内随意新增硬编码颜色。
- 业务图标使用 `@tabler/icons-vue`；状态、按钮及标题图标遵循当前原型，不重复装饰。
- 卡片圆角不超过 8px，按钮组间距统一为 8px。

### 3.2 页面、表格与弹窗

- 顶部导航固定为 48px 高，引导定位或内部滚动不得改变导航栏高度。
- 页面全宽自适应，标题字号与顶部间距在数据标注、模型训练页保持一致。
- 表头与内容共用列模板；数据行使用交替底色，不使用密集行分割线。
- 长列表在指定内容区内部滚动，分页固定在页面内容底部。
- 确认弹窗宽度 400px；模态弹窗按 480px、600px、800px 三档使用。
- 版本详情弹窗最高 600px，标题与底部行动区固定，内容区内部纵向滚动。
- 内容较少的训前检查弹窗按内容自适应高度，不保留无意义空白。
- 弹窗按钮位于右下角，按钮间距 8px；关闭操作只保留右上角关闭图标。

## 4. 数据标注页 `#/annotation`

### 4.1 列表结构

- 标题为“标注数据集”，主操作为“导入数据”。
- 表格列依次为：数据名称、上传时间、描述、已标注/总图片数、样本质量评估、操作。
- 不显示“分析类型”列。
- 已标注数量以进度条和 `已标注数/总图片数` 同时呈现。
- 操作为“标注 / 训练 / 更多”；“详情”位于“更多”菜单。
- 演示数据不少于 15 条，每页 10 条，超出后分页，并包含质量为“优秀”的数据集。
- 搜索命中数据名称或描述；搜索后页码回到第 1 页。

### 4.2 质量摘要入口

- “样本质量评估”表头右侧信息图标，悬停展示六维评估标准。
- 每行显示质量标签“优秀 / 一般 / 待优化 / 待评估”。
- 非优秀状态在标签右侧显示 `N项待优化`；优秀状态不显示“质量达标”等附加文案。
- 点击整块质量摘要打开该数据集的完整质量报告。
- 从模型版本中的训练数据集名称跳回本页时，通过 `datasetId` 定位并直接打开对应质量报告；数据集已删除则 Toast 提示“数据集已删除，无法跳转”。

### 4.3 导入数据

- 使用 480px 弹窗，支持图片、ZIP、DWD 选择；数据包文件名可作为数据集名称。
- 不在上传阶段弹出重复数据二次确认，也不执行文件名和分辨率自动规范。
- 损坏或无法解析的图片自动清理，上传后以结果弹窗展示处理文件清单。
- 图片列表独立滚动，标题和底部行动区固定。
- 上传完成后自动打开新数据集的详情与质量报告。

## 5. 样本质量评估

### 5.1 设计目标

样本质量评估不是单一分数，而是一套“发现问题 → 解释原因 → 给出行动 → 操作后重新评估”的闭环。用户应能在列表中快速判断风险，在完整报告中定位问题，并直接进入补图、去重或标注流程。

评估结果由六个一级维度组成：

1. 样本数量。
2. 样本时间分布。
3. 样本重复度。
4. 类别均衡度。
5. 目标画幅占比。
6. 标注质量，其中包含“完整性”和“规范性”两个子指标。

### 5.2 等级、分值与总评合成

| 数据枚举 | 界面文案 | 雷达分值 | 含义 |
| --- | --- | ---: | --- |
| `excellent` | 优秀 | 100 | 当前维度达到训练建议标准 |
| `normal` | 一般 | 60 | 可继续，但建议优化 |
| `poor` | 待优化 | 30 | 风险较高，应优先整改 |
| `notReady` | 待评估 | 不计分 | 缺少标注或必要数据，暂不能判断 |

总评严格按以下优先级合成：

1. 任一维度为 `notReady`，总评为“待评估”。
2. 无 `notReady` 且任一维度为 `poor`，总评为“待优化”。
3. 六项均为 `excellent`，总评为“优秀”。
4. 其余组合为“一般”。

`issueCount` 等于六维中所有非 `excellent` 维度数量。该数量用于列表摘要、质量报告“待关注”计数和训前检查摘要，不等于阻塞训练的问题数量。

### 5.3 六维计算规则

#### A. 样本数量

| 条件 | 等级 | 行动建议 |
| --- | --- | --- |
| `图片数 > 100` | 优秀 | 样本充足，可支持稳定训练 |
| `20 <= 图片数 <= 100` | 一般 | 建议补充至 100 张以上 |
| `图片数 < 20` | 待优化 | 样本量极低，优先补采 |

非优秀状态的直接行动为“添加图片”。

#### B. 样本时间分布

按采集时间归入上午 7:00-11:00、正午 11:00-14:00、下午 14:00-20:00 三个时段。

| 条件 | 等级 |
| --- | --- |
| 三个时段均有样本，且每个时段占比均 `> 20%` | 优秀 |
| 仅覆盖两个时段，且两个已覆盖时段占比均 `>= 30%` | 一般 |
| 任一时段占比 `< 10%`，或单一时段占比 `> 70%` | 待优化 |
| 其他未达到优秀的分布 | 一般 |

状态行显示三个时段的实际百分比。建议文案指明缺失或占比最低的时段，并给出建议补充数量。直接行动为“添加图片”。

#### C. 样本重复度

重复率计算口径：`重复图片数 /（保留图片数 + 重复图片数）`。

| 条件 | 等级 |
| --- | --- |
| 重复率 `< 10%` | 优秀 |
| `10% <= 重复率 < 20%` | 一般 |
| 重复率 `>= 20%` | 待优化 |

状态行显示 `AI去重 N 张 / 高相似冗余 N%`。非优秀状态的直接行动为“图片去重”。

去重交互分三步：

1. 确认：展示预计处理数量及待去重文件列表。
2. 处理中：锁定误关闭，显示扫描和更新提示。
3. 完成：展示实际移除数量和文件结果；点击“完成”后提示“样本质量已重新评估”。

去重完成后必须同步更新图片总数、重复统计和六维质量结果，不仅修改展示文案。

#### D. 类别均衡度

未产生任何标注时为“待评估”。产生标注后，按分析类型采用两套规则：

- 缺陷、读数、声音类：以最少标签数量评估。`>20` 为优秀，`<10` 为待优化，其余为一般。
- 状态等分类任务：同时评估最少标签数量和最小类别占比。数量 `>20` 且占比 `>20%` 为优秀；数量 `<10` 或占比 `<10%` 为待优化；其余为一般。

状态行显示最少标签数量；分类任务同时显示最小占比。建议文案需指出具体短缺标签。非优秀状态的直接行动为“进入标注”。

#### E. 目标画幅占比

仅统计有框选标注的目标。未产生框选标注时为“待评估”。以 `BBox面积 / 图片面积 < 5%` 的小目标占比评估：

| 条件 | 等级 |
| --- | --- |
| 小目标占比 `= 0` | 优秀 |
| `0 < 小目标占比 < 20%` | 一般 |
| 小目标占比 `>= 20%` | 待优化 |

状态行显示 `BBox < 5%：小目标数/目标总数（占比）`。非优秀状态的直接行动为“进入标注”，用于核对问题框或调整采集距离。

#### F. 标注质量

未标注任何图片或没有有效标注时，整个维度为“待评估”。有标注后拆为两个子指标：

| 子指标 | 计算方式 | 优秀 | 一般 | 待优化 |
| --- | --- | --- | --- | --- |
| 完整性 | 已标注图片数 / 图片总数 | `>90%` | `70%-90%` | `<70%` |
| 规范性 |（标注总数 - 不规范标注数）/ 标注总数 | `>95%` | `90%-95%` | `<90%` |

规范性检查包含：

- 标注框越出图片边界。
- 非读数类任务中，两个标注框重叠度超过 95%。
- 重叠度超过 65% 且标签关系存在“正常/异常、开启/关闭、佩戴/未佩戴”等语义冲突。

标注质量一级等级取完整性和规范性中较差的一项，雷达分值也取两者较低分。展开后：

- 标题行显示“标注质量 + 等级标签”。
- 完整性/规范性摘要位于最右侧展开箭头左边，箭头固定在行最右端。
- 完整性显示进度条及 `已标注 x/y`，建议达到 90% 以上。
- 规范性只展示一次核验结论，不重复堆叠“100%”“优秀”等信息。
- 非优秀状态提供“进入标注”，直接跳转当前数据集标注页。

### 5.4 完整质量报告的展示与展开逻辑

- 报告使用 800px 大号弹窗，左侧为总评、六轴雷达和数据集元信息，右侧为“六维质量诊断”。
- 雷达轴顺序固定为六个一级维度；优秀 100、一般 60、待优化 30、待评估不闭合。
- 维度排序为：待优化 → 一般 → 待评估 → 优秀，先把需要处理的问题放在可见区域。
- 初次打开时，默认展开排序后的第一个非优秀维度；若全部优秀，则默认全部收起。
- 维度采用手风琴交互，同一时间只展开一项，避免内容过长和重复信息干扰判断。
- 每个标题行从左到右为：维度名称、等级标签、状态摘要、展开箭头；状态摘要和箭头靠右，箭头始终处于最右端。
- 优秀维度仍可展开查看结果，但不显示整改按钮，也不显示“质量达标”副文案。
- “六维质量诊断”右侧显示 `N项待关注`；全部优秀时显示“全部达到优秀”。
- 信息图标悬停展示各维度标准，不再额外弹出二次风险确认弹窗。

### 5.5 行动闭环

| 问题维度 | 主行动 | 结果 |
| --- | --- | --- |
| 样本数量、样本时间分布 | 添加图片 | 打开当前数据集的追加上传弹窗 |
| 样本重复度 | 图片去重 | 完成确认、处理、结果三阶段并重新评估 |
| 类别均衡、目标画幅、标注质量 | 进入标注 | 关闭报告并进入当前数据集标注工具 |

标注保存、追加图片、去重等会改变数据事实的操作完成后，应调用同一套质量评估逻辑刷新结果。前端不得在不同入口维护互相独立的质量结论。

### 5.6 与训练流程的联动

- 训练弹窗的数据集下拉项及已选项，在下拉箭头左侧显示质量标签。
- 点击“开始训练”后先执行训前检查。训前检查只读取当前 `qualityStatus` 摘要，不在弹窗内重新计算六维质量。
- 训前检查顶部显示样本质量等级、非优秀维度数、样本数量及标注进度，并提供“查看完整质量报告”。
- 点击“查看完整质量报告”直接打开当前数据集报告，不再出现“AI预警：质量风险较高，大概率返工”等二次提示弹窗。
- 样本质量为“一般”或“待优化”时属于提醒，可点击“继续训练”；质量问题本身不等同于环境阻塞。
- 样本质量为“待评估”且没有其他阻塞项时，主按钮显示“进入标注”，引导用户补齐标注后再训练。
- 环境存在真正阻塞项时，主按钮置灰并显示“存在预警，暂不可训练”。
- 从数据标注页确认继续训练后，创建模型版本并跳转 `#/training?guideVersionId=...`；自动翻到模型所在页、展开模型、滚动到新版本并显示“训练中”。

### 5.7 研发数据契约

后端接入时，建议以单一 `qualityStatus` 返回总评和完整六维结果，前端只负责排序与展示。核心字段：

```ts
type DatasetQualityStatus = {
  overallLevel: 'excellent' | 'normal' | 'poor' | 'notReady'
  issueCount: number
  summary: string
  diagnosisDurationMs: number
  performanceTargetMs: 5000
  dimensions: Array<{
    key: 'sample-count' | 'time-distribution' | 'duplicate-ratio'
      | 'label-balance' | 'bbox-ratio' | 'annotation-quality'
    name: string
    score: 100 | 60 | 30 | null
    level: 'excellent' | 'normal' | 'poor' | 'notReady'
    status: string
    suggestion: string
    subMetrics?: Array<{
      key: 'completeness' | 'standardization'
      rate: number
      score: 100 | 60 | 30 | null
      level: 'excellent' | 'normal' | 'poor' | 'notReady'
      status: string
      suggestion: string
    }>
  }>
}
```

接口实现注意事项：

- `key`、等级枚举和阈值口径需保持稳定，避免前端通过文案判断业务状态。
- `status` 用于标题行短摘要，`suggestion` 用于展开后的解释，两者避免重复。
- `issueCount` 由服务端或统一领域层计算，所有入口使用同一结果。
- 去重、标注保存、图片追加完成后，应返回新版本质量结果或触发重新评估任务。
- 质量评估失败时保留上一版可用结果，并单独返回计算状态；不要将接口异常映射为“待优化”。

## 6. 标注工具 `#/annotation/:datasetId`

- 顶部工具行 64px；左侧工具栏 44px；右侧标签配置 260px；其余空间用于画布。
- 画布图片不加额外底色或外边距，底部缩略图列表保持可见。
- 顶部只展示次级“样本质量”按钮，点击打开完整报告，不持续暴露质量等级。
- 工具栏底部单独放置“教程示例”，与常用标注工具分组。
- 每种分析类型第一次使用时自动打开教程；关闭后以一次性 Popover 指向重新打开入口。
- 教程浮窗可在视口范围内拖动，正确/错误示例成对展示并支持多组切换。

## 7. 模型训练页 `#/training`

### 7.1 模型与版本列表

- 页面标题与数据标注页字号、顶部间距一致；顶部主操作为“新建训练”。
- 至少展示 12 个模型，每页 10 个，超出后分页。
- 模型行展示模型名称、描述、创建时间及“训练新版本 / 更多”，不在模型行显示训练状态。
- 模型名称字号采用列表层级，不使用页面标题尺寸。
- 展开模型后显示版本表头：版本、训练数据集、训练状态、训练时间、操作。
- 训练状态仅包含“训练中 / 训练完成 / 训练失败”；不显示“待发布、当前生效、历史版本”等发布语义。
- 已发布状态显示在操作区原“发布”位置，带成功图标，并与其他文字按钮左对齐。
- 发布、验证按钮只显示文字；“重新发布”统一为“发布”。
- 非表计类模型的“验证”按钮置灰占位，悬停提示“非表计类模型验证功能即将上线”。
- 训练数据集名称可点击跳转数据标注页并打开对应数据集；数据集已删除则 Toast 提示无法跳转。

### 7.2 滚动规则

- 外层模型列表独立纵向滚动，顶部导航和页面工具栏尺寸保持稳定。
- 模型展开后，模型行和版本表头在该模型区域顶部保持可见，版本列表内部滚动。
- 鼠标位于版本列表时优先滚动版本列表；到达顶部继续向上或到达底部继续向下时，把滚轮增量传递给外层模型列表。
- 鼠标位于模型行区域时直接滚动外层模型列表。
- 表头与版本行共用列模板，横向滚动时不得错位，操作列必须可访问。

### 7.3 新建训练与引导定位

- 可选择已有模型或输入新模型名称；已有模型训练创建新版本，不覆盖历史版本。
- 数据集选项显示质量标签；可选择电力基础模型或通用模型，高级参数默认折叠。
- 全局同一时间只允许一个训练任务；已有任务训练中时，入口置灰并说明原因。
- 训前检查通过或用户确认继续后，创建的新版本立即显示“训练中”和进度条。
- 页面自动切换到模型列表、清空搜索、切换到目标分页、展开目标模型，并将新版本定位到版本列表中部。
- 目标版本短暂使用引导高亮，约 3 秒后恢复；顶部导航始终保持 48px，不因滚动定位发生拉伸或位移。
- 原型约 10 秒后将新版本由“训练中”更新为“训练完成”。

### 7.4 版本详情与发布

- 版本详情标题不使用左侧图标，副标题显示“模型名称 / 版本号”。
- 弹窗最高 600px，内容区滚动，模块间距紧凑。
- 版本信息展示模型名称、版本、发布状态、发布时间，不显示创建时间或重复的“当前生效”文案。
- 训练状态放在“训练配置”模块；训练中时在顶部显示进度。
- 训练数据集名称可点击跳转，删除后 Toast 提示。
- 已训练完成且未发布的版本可发布；发布后在操作区显示“已发布”。

## 8. 训前检查

样本质量与环境检查解耦：质量评估负责训练数据风险，训前检查负责运行环境是否允许启动训练。

当前检查范围：

- GPU 占用超过 90%。
- 磁盘可用空间低于 5GB。
- 内存占用超过 90%。
- 训练镜像异常。

当前版本不检查“标品算法包版本不兼容”，界面中不得出现 1.1.6/1.1.7 兼容提示。

放行规则：

- 全部通过：不展示检查弹窗，直接开始训练。
- 只有提醒项：展示紧凑弹窗，允许“继续训练”。
- 存在阻塞项：主按钮置灰，不允许继续。
- 样本质量“待优化”只做风险提醒，不阻塞训练。
- 样本质量“待评估”且环境无阻塞时，引导“进入标注”。
