## Design Context

### Users
DW Detection is used by external delivery personnel with limited algorithm experience. They need to move confidently through dataset upload, annotation, training, deployment, validation, and inference while avoiding labeling mistakes and unnecessary retraining.

### Brand Personality
Calm, precise, and dependable. The interface should make technical workflows feel understandable without becoming playful, promotional, or visually loud.

### Aesthetic Direction
Use the DW Build dark, solid-surface visual language with compact information density, restrained semantic color, and clear operational hierarchy. Favor full-width work surfaces, scannable tables, and progressive disclosure. Keep radii at 8px or below, use Tabler icons, and reserve translucent treatments for overlays and floating tools when the active theme calls for them.

### Design Principles
- Keep repeated operational workflows compact, predictable, and easy to scan.
- Explain risk and next actions in plain language for users without algorithm expertise.
- Use semantic tokens and existing Element Plus patterns instead of component-local color systems.
- Reveal detail progressively while keeping the primary action and current state visible.
- Preserve complete workflows across standard desktop, short-height, and narrow viewports.
